# 有料プラン・夢の交流・GPT運用（v4.3）

## プラン

価格は指定された日本円の請求総額としてApp Store Connect / Google Play Consoleのサブスクリプション価格に登録します。年額は年1回の一括請求です。

| 機能 | フリー | スターター | スタンダード |
|---|---:|---:|---:|
| 月額 | 0円 | 490円 | 980円 |
| 年額 | 0円 | 4,900円 | 9,800円 |
| 夢の記録（日付ごと） | 1件 | 3件 | 10件 |
| 日記の保存（日付ごと、1ページを保存できる回数） | 3回 | 5回 | 10回 |
| AI読み解き（日付ごと、夢1件につき1回） | 1回 | 3回 | 10回 |
| 手書きOCR（月） | なし | 5回 | 20回 |
| みんなの夢（他の人の投稿） | その日の投稿からランダム3件・夢の本文は15文字まで | 30件 / 日 | 150件 / 日 |
| 新しく公開する夢（日） | 1件 | 1件 | 3件 |
| 同時公開数 | 10件 | 10件 | 50件 |
| スタンプで反応（日） | なし（数を見るだけ） | 30回 | 100回 |
| GPT費用の月間内部上限 | US$0.25 | US$0.75 | US$2.00 |

日記は1日1ページで、同じ日付のページを保存するたびに1回と数えます（端末ごとの `{アカウント領域}.diary-saves` に記録）。無料枠を超えて保存しようとすると、入力中の文章を保持したままプラン画面へ遷移し、戻ると復元されます。同じ日付に2件目の夢を保存しようとした場合も同様です。

AI読み解きは全プランで夢の記録とセットです。回数は夢の日付（利用者のカレンダー日付、0時に切り替わる）ごとに数え、`usage/{uid}_d_{日付}` に記録します。費用上限は従来どおり月単位（`usage/{uid}_m_{月}`）です。

夢を公開することは全プランでできます。有料プランで開くのは「他の人の夢を全文で読むこと」と「スタンプで反応すること」です。コメント・通報・ブロックの機能はありません。

フリー会員の「みんなの夢」は `GET /api/community/teaser?day=YYYY-MM-DD&tz=分` で、その日に公開された投稿（非表示・利用停止の作者を除く）から、利用者IDと日付から決まる乱数で3件を選びます。他の人の投稿は、表示名とタイトルはそのまま、夢の本文だけを先頭15文字（`TEASER_CHARS`）にして返します。同じ日に何度読み込んでも同じ3件で、全文は返しません。「…続きを読む」「もっと見る」はプラン画面へ遷移します。

自分が公開した投稿は、この一覧に「自分」の印つきで全文のまま並びます（3件の枠外、最新20件）。自分の投稿はフリー会員でも詳細を開けます。抜粋カードにも、ついたスタンプの種類と数が表示されます（フリー会員は反応できません）。

全プランで16タイプ・2シリーズのキャラクター、睡眠レベル、端末内分析、画像添付（OCRを除く）、過去の閲覧・編集、JSONバックアップを使えます。

記録枠は「その日付に保存されている件数」です。編集は新規枠を使わず、削除すればその枠が空きます。過去の記録やバックアップの復元は削除せず保持します。端末内記録の制限はUIの製品ルールであり、端末データの改変まで防止するDRMではありません。通信不能で会員確認できない間の新規記録は無料枠を使います。既存の記録の編集は可能です。

交流枠は毎日0:00 UTC、AI枠は毎月1日0:00 UTC（日本時間9:00）にリセット。月額/年額とも同じ枠で、繰り越しなし。プラン変更で使用数はリセットしません。年額を12か月分まとめて使うこともできません。交流はオンラインかつ非匿名ログインが必要です。

投稿表示は一覧で返した件数＋詳細表示回数。再読み込みも表示枠を使います（スタンプを押したあとは再取得しません）。自分の公開投稿は「みんなの夢」の一覧にも「自分の投稿」の印つきで並びますが、表示枠は使いません（自分の投稿の管理も対象外）。公開本文4,000文字、タイトル80文字、ニックネーム30文字。

**スタンプ**：面白い😂・すごい🤩・不思議🔮・謎🤔・怖い😱・楽しい🥳・同じです🙋・似てる👯・見てみたい👀・グッド👍・見たことある💭・ハート❤️ の12種類（定義は `public/core/plans.js` の `STAMPS`、保存はスタンプID）。1ユーザー1投稿につき1つで、別のスタンプを押すと置き換え、同じものをもう一度押すと取り消し。スタンプを付けるたびに日次枠を1回使い、取り消しは枠を使いません。自分の投稿には付けられません。投稿の長押し（450ms）または「＋」ボタンで選択シートを開き、投稿の下のスタンプ数を押しても同じスタンプを付け外しできます。

## 公開とプライバシー

- 公開は夢ごとに決めます。読み解きページの「この夢をみんなの夢に公開する」にチェックを入れて保存すると、夢の本文がそのままニックネーム・タイプ・キャラクターとともにみんなの夢へ投稿されます。ログインしていれば全プランで使えます（有料会員は初期状態でオン、フリー会員は初期状態でオフ）。チェックを外して保存すると非公開に戻ります。公開状態は記録の `shared` フラグとしてアカウントに同期します。日次の公開枠超過や判定サービスの失敗で投稿できなかった場合は、夢の保存だけを行い、チェックを外してエラーを表示します。
- 保存した夢の詳細 → 公開設定からは、従来どおり公開用の文章・呼び名を編集して個別に公開・非公開にできます。設定画面には公開に関する項目はありません。
- みんなの夢の一覧は、投稿者のキャラクター（16タイプ）・ニックネーム・夢の本文だけを表示します。各カードの下にスタンプの種類と数を表示し、有料会員はそこから反応できます。
- 公開した投稿を読めるのはログイン中の会員だけです。検索エンジンや匿名ユーザーには返しません。フリー会員には上記の15文字の抜粋だけを返します。
- 投稿には公開用の本文・タイトル・ニックネーム・タイプ・選んだキャラクターだけを複製。日記、AI分析、睡眠データ、年代、メールアドレス、添付写真は含めません。
- 夢を編集しても公開済み文章は変わりません。再度公開設定から明示的に更新します。
- 非公開に戻すと本文/タイトル/ニックネームを公開用文書から除去し。元の夢は保持。
- 公開は作者のプランに左右されません。支払期間が終わってフリーに戻っても、公開したままの投稿は他ユーザーから見えます（公開は全プランの機能のため）。非表示にするには本人が非公開に戻します。利用停止（`suspended`）の作者の投稿は表示しません。
- ログイン中に夢を削除するときは先に公開状況をオンライン確認し、該当投稿を非公開にします。通信失敗時は削除を止め、公開投稿だけが取り残されることを防ぎます。
- 投稿APIには `Cache-Control: no-store`。Service WorkerでもAPIをキャッシュしません。ただし、閲覧済み文章のスクリーンショットなどを取り消すことはできません。
- 投稿はOpenAI Moderationで確認してから公開。判定サービスの失敗時は公開しません。通報・ブロック・コメントの機能はありません。運営者は Firestore で `communityPosts/{id}.hidden=true` を設定すると投稿を非表示にでき、`memberships/{uid}.suspended=true` で作者を利用停止にできます。
- アカウント削除（設定 → アカウントを削除）は `POST /api/account/delete` で、本人の `/users/{uid}` 配下、公開投稿（スタンプ含む）、`memberships`・`communityStats`・当日/当月の `usage` を消してから Firebase Auth のユーザーを削除します。サーバーに届かない場合は端末側で `deleteUser` を試み、再ログインが必要ならその旨を表示します。

## GPT費用の考え方

2026-09-18確認。GPT-5.6 Lunaは2026-07-30の値下げ後、入力100万トークンUS$0.20、出力US$1.20（GPT-4.1 miniのUS$0.40 / US$1.60より安価）。画像入力と構造化出力に対応します。推論モデルのため `reasoning_effort: "none"` を指定し、推論トークンによる費用・出力枠の変動をなくして採用しました。[公式モデル/料金](https://developers.openai.com/api/docs/models/gpt-5.6-luna)

- モデルを `gpt-5.6-luna-2026-07-09` に固定。変更時は費用計算（`server/openai.js` の単価係数）も見直すこと。
- 読み解き（心の状態＋今日の占い、11項目）の出力1,400トークン、OCR出力1,600トークン。入力には夢・睡眠・前日の日記・直近7日分の日記（各2,000文字まで）を含みます。入力テキスト（指示/スキーマを含む）30,000 UTF-8バイト以内。画像は低詳細設定。
- UTF-8バイト数をテキストのトークン数の保守的上限として扱い、画像/メッセージの予備枠を加えて呼び出し前に費用枠を確保。実請求額の会計ではなく、過大寄りの利用制限です。
- 回数・ユーザー別費用・サービス全体費用をFirestoreの同一トランザクションで確保。同時アクセスや再起動による回数超過を防ぎます。
- 自動リトライなし、45秒タイムアウト。API実行開始後は失敗/タイムアウトも回数・確保費用を消費（提供元で請求が発生したか判別できないため）。入力不正・枠不足は送信前に拒否。
- 夢の記録ページの「この夢を診断」だけがAI枠を使います（診断結果ページの「保存する」やOCR以外の操作は呼びません。診断結果が残っている夢を開き直したときも呼びません）。AIが失敗・拒否したときは端末内の振り返りを診断結果として表示し、保存はできます。`store: false`でAPI出力の保存を要求しません。
- 本番の `AI_GLOBAL_MONTHLY_USD` は初期値20ドル。OpenAI側の月間リロード上限と同じ値にしておくと、枠切れ時にアプリ側が先に分かりやすいメッセージで止まります。利用者増加時に料金収入と照合して変更。OpenAIプロジェクト側の予算/通知も別途設定してください。Moderation、Firebase、ストア手数料、ホスティング等はこのGPT上限に含みません。

### 試算（為替1ドル=160円、販売手数料30%を仮定した厳しめのシナリオ）

為替・手数料は試算上の仮定であり、現在の為替相場や実契約の手数料を示すものではありません。税、返金、サポート、サーバー費を引く前です。

| 年額会員の月換算 | スターター | スタンダード |
|---|---:|---:|
| 売上 | 約408円 | 約817円 |
| 手数料30%控除後 | 約286円 | 約572円 |
| GPT月間費用上限 | 80円 | 200円 |
| その他経費に充てられる残額 | 約206円 | 約372円 |

通常の読み解きを入力9,000（システムプロンプト約5,500＋夢・日記・直近の夢の要約）/出力1,600トークンと仮定すると1回約0.56円（入力0.27円＋出力0.29円）、月30回約17円、90回約50円。サーバーは文字種から上限トークンを見積もって費用を予約し（`estimateTokens`）、月間費用上限に対して照合します。長文・OCRに余裕を残しつつ内部上限を設けています。利益は保証できないため、実際の入力量・会員数・解約率・Firebase使用量で月次レビューしてください。無制限のGPTや無制限の投稿閲覧は設定していません。

## 本番接続手順

### 1. Firebase

既存プロジェクト `yumetan-a31f0` の `(default)` に接続します。新しいデータベースは作成していません。本作業の管理アカウントでは403のためデータベースEditionと本番IAMを確認できませんでした。既存アプリが使う通常のFirestore API向けの実装です。運用者の権限でEdition/APIモードとIAMを確認してください。

- Render等に `FIREBASE_PROJECT_ID`、必要に応じ `FIRESTORE_DATABASE_ID`、`FIREBASE_SERVICE_ACCOUNT_JSON` またはApplication Default Credentialsを設定。クライアントと必ず同じプロジェクトにすること。
- サービスアカウントにはFirestore読み書き、Firebase Authのトークン失効/無効ユーザー確認に必要な権限を設定。秘密JSONは公開フォルダやGitへ置かないこと。
- `npx firebase-tools deploy --project yumetan-a31f0 --only firestore:indexes` で追加インデックスを反映。
- 既存 `firestore.rules` は変更していません。許可は本人の `/users/{uid}/...` に限定され、以下のサービス用ルートはクライアントSDKからすべて拒否される設計です。本番に同じルールが反映されていることを確認。

| サーバー専用コレクション | 用途 |
|---|---|
| `memberships` | RevenueCat由来のプラン・周期・期限・解約予定・停止状態 |
| `usage` / `serviceBudgets` | 日次/月次回数とGPT費用予約 |
| `communityPosts` と `reactions` サブコレクション | 公開用コピーとスタンプ（1人1つ） |
| `communityStats` | 同時公開数 |

期限/回数はサーバー時刻で判定し、ブラウザのプラン名・UIDヘッダー・APIキーは権限の根拠にしません。Firebase IDトークンは失効を含め検証します。

### 2. OpenAI

`OPENAI_API_KEY` をサーバー環境へ設定。入力/出力制限に一致するモデルを利用できるプロジェクトを使ってください。個人キー入力欄、Claude API、キーによる無料枠迂回は廃止しています。

- モデルは `OPENAI_MODEL`（既定 `gpt-5.6-luna` のエイリアス。日付スナップショットを固定したい場合だけ指定）。プロジェクトがそのモデルを使えない（404 / model_not_found）ときは `OPENAI_FALLBACK_MODEL`（既定 `gpt-5.6-terra`。Lunaの約10倍の単価なので、費用予約はLuna基準のまま。`""` で無効）で1回だけ再試行します。モデルが `reasoning_effort` を拒否した場合は同パラメータを外して1回再試行します。
- 429/5xx/タイムアウトはSDKが1回自動再試行。キー不正・残高不足（401/403/`insufficient_quota`）は再試行せず `aiUnavailable` を返します。
- 失敗の理由（status・code・種別。夢の本文やキーは含めない）はサーバーログに `OpenAI request failed` として残ります。以前は握りつぶしていたため原因が追えませんでした。
- `GET /api/health` の `aiStatus` で、キーが設定済みか（`configured`）と、そのキーでモデルが見えるか（`available`。`modelNotFound` / `keyRejected` / `unreachable` / `noKey`）を10分キャッシュで確認できます。読み解きを1回も消費せずにデプロイを検証できます。
- 利用者側：AI診断に失敗すると診断結果ページに理由（ログイン必要・枠切れ・AI未設定・失敗）と「AI診断をもう一度」を表示し、端末内の振り返りを代わりに表示します。

読み解きのシステムプロンプトは `server/prompts.js`。夢心理の知識（`knowledge/dream_psychology.md` の要約）、心の状態の読み方の手順、`mood_weather` の判定基準、占いの組み立て方（夢の要素・動き・結末の感情・具体物からラッキーヒントを導く）、言語別の文体と文字数、安全対応を含みます。夢1件に加えて、16タイプのプロフィール、前日の日記、直近7日分の日記、直近7件の夢の要約（テーマ・タイトル・以前の天気）、曜日と月相を渡します。

### 3. RevenueCat（App Store / Google Play のサブスクリプション）

購入はiOS / Androidアプリ内のストア課金だけです。Web版に決済はなく、アプリで購入したプランを同じアカウントでWebでも使えます。Stripeは廃止しました。

**ストア側**

- App Store Connect: 有料App契約に同意し、自動更新サブスクリプションを4つ作成（月490円 / 年4,900円のスターター、月980円 / 年9,800円のスタンダード）。製品IDは `com.doyle.yumetan.starter.monthly`、`com.doyle.yumetan.starter.yearly`、`com.doyle.yumetan.standard.monthly`、`com.doyle.yumetan.standard.yearly`（別のIDでも、`starter`/`standard` と `monthly`/`yearly`（または `year`/`annual`）を含んでいればアプリが一致させます）。Sandboxテスターも作成。
- Google Play Console（Androidを配布する場合）: 同じ製品IDで定期購入を作成し、基本プランを月/年で設定。ライセンステスターを登録。

**RevenueCat側**（プロジェクト: ユメタン）

- Apps: iOS / Android のアプリを登録し、App Store Connect の In-App Purchase Key と Google Play のサービスアカウントを接続。
- Products: ストアの4製品を取り込む。
- Entitlements: `starter` と `standard` の2つを作り、月/年の製品をそれぞれ紐づける。サーバーはこのEntitlement名でプランを決め、製品IDから月/年を判定します。Entitlementが未設定でも、有効なサブスクリプションの製品IDに `starter` / `standard` が含まれていれば、サーバーはその製品からプランを判定します（TestFlight の Sandbox 購入も同じ）。
- Offerings: `default` に4製品のPackageを追加（カスタム識別子 `starter_monthly` / `starter_yearly` / `standard_monthly` / `standard_yearly`）。初期のTest Store用Package（Monthly / Yearly / Lifetime）は削除してよい。
- API keys: 各アプリの公開SDKキー（`appl_…` / `goog_…`）はアプリのビルド時に `REVENUECAT_IOS_KEY` / `REVENUECAT_ANDROID_KEY` として `npm run mobile:build` へ渡す。秘密APIキー（`sk_…`）はサーバーの `REVENUECAT_SECRET_API_KEY` にだけ設定。
- Test Store 用キー（`test_…`、RevenueCat → API keys → Test Store）は **Debugビルド専用**。TestFlight や App Store 向けの Release ビルドに入れると、SDKが起動時に「Wrong API Key」を表示してアプリを終了させます（[RevenueCat Test Store](https://www.revenuecat.com/docs/test-and-launch/sandbox/test-store)）。`npm run mobile:build` は `test_` キーを拒否し、シミュレータ等で Test Store を使うときだけ `REVENUECAT_ALLOW_TEST_STORE=1` を付けてビルドしてください。TestFlight で実機確認するときは `appl_…` キーで `npm run mobile:sync` し直してから Xcode でアーカイブします（Sandboxテスターで購入テストできます）。
- Xcode の画面を使わずにアップロードする場合は `IOS_TEAM_ID=<Team ID> npm run ios:upload`（`scripts/ios-upload.sh`）。Release 構成でアーカイブし、自動署名で App Store Connect へ直接アップロードします。ビルド番号は未指定なら現在日時になります。
- Integrations → Webhooks: URL `https://<サーバー>/api/billing/revenuecat`、Authorization header に自分で決めた長いランダム文字列を入力し、同じ値をサーバーの `REVENUECAT_WEBHOOK_AUTH` に設定。

**本番に近い購入テスト（Appleの購入画面を出す）**

「登録する」を押しても App Store の購入シートが出ず、そのまま有料プランになった場合は、ビルドが **RevenueCat の Test Store** につながっています。Test Store はストアを通さずに購入を成立させる開発用の仕組みで、課金も購入画面もありません。アプリはこの状態をプラン画面に「テスト用ストアに接続しています」と表示します（`purchases.testStore()`）。実際のストアで確認する手順は次のとおりです。

1. `REVENUECAT_IOS_KEY` に **`appl_…`（Test Store ではない公開SDKキー）** を設定する。RevenueCat → Project settings → API keys の、iOS アプリに紐づくキーです。`REVENUECAT_ALLOW_TEST_STORE` は付けない（付いていると `test_…` キーが通ってしまいます）。GitHub Actions でビルドする場合は Repository secrets の `REVENUECAT_IOS_KEY` を同じ値にします。
2. RevenueCat の iOS アプリに App Store Connect の In-App Purchase Key を接続し、Products / Entitlements / Offerings に実際の4製品が入っていることを確認する（Test Store 用の Package は削除）。
3. App Store Connect で4つのサブスクリプションが「提出準備完了」以上であること、価格（日本 490 / 4,900 / 980 / 9,800円）が入っていること、有料App契約に同意済みであることを確認する。1つでも未完成だと購入シートが出ず `productUnavailable` になります。
4. `API_URL=… REVENUECAT_IOS_KEY=appl_… npm run mobile:sync` でビルドし直し、TestFlight（または Xcode の Release 構成）で実機へ入れる。シミュレータでは Sandbox 購入を確認できません。
5. 実機の 設定 → App Store → Sandbox アカウント に **Sandboxテスター** でサインインし、アプリからプランを購入する。Apple の購入シートが「[環境: Sandbox]」付きで表示されれば本番と同じ経路です。
6. 購入後はプラン詳細ページの「残り」と `paidUntil` で、サーバー（`POST /api/billing/sync` → RevenueCat REST API）が契約を認識したかを確認する。ここが更新されなければ、Webhook / 秘密APIキー / `FIREBASE_*` の設定を見直します。
7. 解約・期限切れの確認は Sandbox の加速された更新間隔（月額は数分）で行えます。App Store Connect の Sandbox テスター設定で更新速度を変えられます。

**プランの変更・解約**

- プラン画面の登録ボタンは、現在のプラン以外の有料プランで常に有効です（有料会員はスターター⇄スタンダードの変更ができ、ボタンは「変更する」表示）。フリーには登録ボタンがなく「詳細」だけです。
- 解約はストアのサブスクリプション設定から行い、期間終了後は RevenueCat の Webhook / 同期でサーバーの `paidUntil` が過ぎるため、自動的にフリープランに戻ります。

**サーバーの動作**

- アプリはRevenueCatの App User ID にFirebase UIDを使います。購入・復元後に `POST /api/billing/sync` を呼び、サーバーがRevenueCat REST API（`GET /v1/subscribers/{uid}`）で契約を照会して `memberships/{uid}` を更新します。ストア側の反映が遅れることがあるため、アプリは「登録する」を押してから反映されるまで全画面のローディング（ストアに接続 → プランを反映）を表示し、有料プランになるまで最大6回（2.5秒間隔）同期を繰り返します。ストアが返した購入情報（CustomerInfo）のプランは、サーバー反映を待つ間もアプリ内の表示・端末内の記録枠に使います。
- Webhookは Authorization ヘッダーを定数時間比較で検証し、イベント本文の権利情報は信用せず、含まれるユーザーIDについて同じ照会を行います。匿名ID（`$RCAnonymousID:…`）は無視します。`TEST` イベントは受理のみ。
- 期限切れ・未知の製品は無料扱い。解約予定は `cancelAtPeriodEnd` として表示。古い照会結果が後から届いても上書きしません（`request_date_ms` で判定）。
- Webhook が届かなかった更新（無料インスタンスのスリープ中、配信の打ち切り、数分ごとに更新される Sandbox など）で有料会員がフリーに戻らないよう、`GET /api/account` は保存済みの有料期間が切れていればRevenueCatに照会し直します（期限後10分間は1分に1回まで、それ以外は6時間に1回）。照会するのはRevenueCatに一度でも同期済みの会員だけです（未登録のIDを照会するとRevenueCat側に購読者が作られるため）。
- プランは購入した製品IDで決め、Entitlement名は製品IDにプラン名が無いときの補助です。複数のEntitlementが有効ならスタンダードを優先します。
- `TRANSFER`（別アカウントでの復元）は `transferred_from` / `transferred_to` の両方を照会し直します。
- アプリは、購入後の同期が完了しないまま（アプリ終了・サーバー起動待ちなど）ストアが確認したプランがサーバーより上なら、起動時・アプリに戻ったとき（1分に1回まで）に `POST /api/billing/sync` をもう一度呼びます。プラン変更（スターター→スタンダード）では、サーバーが新しいプランを返すまで同期を繰り返します。
- Sandbox購入も有効化します（Sandboxテスター/ライセンステスターは開発者が登録した人だけが使えるため）。本番配布前にSandboxで購入・復元・解約・期限切れ・Webhook再送を確認してください。

参考: [RevenueCat Webhooks](https://www.revenuecat.com/docs/integrations/webhooks)、[REST API v1](https://www.revenuecat.com/docs/api-v1)、[Capacitor SDK](https://github.com/RevenueCat/purchases-capacitor)。

### 4. 運営・ストア

- `SUPPORT_URL` に問い合わせページを設定。問題のある投稿は `communityPosts/{id}.hidden=true`、作者は `memberships/{uid}.suspended=true` で止めます（どちらも管理者がFirestoreで設定）。
- iOS/Androidでは外部決済ボタンを表示せず、ストア内購入・復元だけを提供します。自動更新・取消条件・事業者/問い合わせ情報をアプリ内とストア掲載情報に明記してください。配布地域/ストア条件の審査は別途必要です。[Appleのガイドライン](https://developer.apple.com/jp/app-store/review/guidelines/)

## 検証の範囲

ロジックとブラウザでは、テスト用Firebase認証・メモリ上のトランザクション・RevenueCat/GPTスタブを使用し、実ユーザーの夢を投稿したり課金したりしません。Firestore APIは本番アクセスできていないため、インデックス/IAM/ストア購入/Webhookは上記手順で実環境の確認が必要です。

### 依存関係

Node.js 22以上が必要です。`npm ci`で再現可能なことを確認。互換範囲の更新を適用しましたが、`npm audit`には8件（moderate 4 / high 3 / critical 1）が残ります。high/criticalは既存の画像生成・Capacitor開発ツール依存です。production側にもGoogle認証のgaxios/uuid由来のmoderateが残り、今回の範囲では破壊的な依存変更をしていません。公開前の依存更新・運用レビュー事項として記録します。
